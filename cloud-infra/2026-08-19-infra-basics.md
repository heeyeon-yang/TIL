# 2026-08-19 인프라 개요 (p.18-26)

## IT 인프라 구성 요소
- 퍼실리티: 건물/설비 (데이터센터 구성 시설물 — 랙, 에어컨, 발전기, 변압기, 소화설비)
- 서버·스토리지: 데이터를 대량으로 저장·처리
- 네트워크: 서버-스토리지 연결 + 인터넷 접속

## 서버-네트워크 / 서버-스토리지 구성
- 프로젝트 규모에 따라 다양한 구성 패턴이 가능 (예: 메일 시스템 하나도 구성 방식이 여러 가지)
- 고려 요소: 이중화 구성, 데이터 영역 분리 구성
- 최선의 구성을 상황에 맞게 선택하는 게 핵심

## 인프라 엔지니어 책임 범위
**운영 시스템 관점**
- 시스템 감시/운영 검토
- 장애 감지 및 대응 전략 (1차/2차 대응 프로세스)

**조직 내 책임 범위**
| 영역 | 담당 |
|---|---|
| 애플리케이션 + 미들웨어 | 개발자 |
| 미들웨어 + 운영체제 + BIOS + 하드웨어 | 서버 엔지니어 |
| 연결 + 네트워크 스위치 | 네트워크 엔지니어 |

## 서버의 종류

**폼팩터**
- 랙 마운트형: 데이터센터/서버룸 랙에 설치
- 타워형: 사내 서버룸, 사무실, 점포
- 서버 높이 단위: 1U = 1.75인치 = 4.445cm (1U → 엔트리 서버 / 2U 이상 → 미들레인지 서버)

**등급별 용도**
| 등급 | 용도 |
|---|---|
| 엔트리 서버 | 웹서버, 애플리케이션 |
| 미들레인지 서버 | 중간 규모 DB 서버, 기간계 서버 |
| 하이엔드 서버 | 대규모 DB 서버, 기간계 서버 |

> **기간계 서버(기간 업무 시스템)**: 재무/업무/생산 관리 등 기업 경영의 핵심이 되는 시스템. = 미션 크리티컬 시스템 = 엔터프라이즈 시스템 = 백본 시스템

## 서버 선정 시 고려사항
- 필요한 하드웨어 자원 사용량 정하기 (용량 추정)
- CPU, 메모리, 디스크, NIC 포트 수
- RAID 유무, PSU 이중화, 보수 연수/수준, 확장성, 물리 사이즈와 중량

## 서버 확장 방식
- **스케일 아웃**: 성능 부족 시 서버 수를 늘려 수용량 증가
  - 예: 웹서버는 엔트리급으로 구축 후 부족하면 대수를 늘려감
- **스케일 업**: 성능 부족 시 부품 증설/교환 또는 상위 기종으로 교체
  - 예: 분산 아키텍처가 어려운 데이터베이스

## DB 이중화 (Active / Standby)
- DB는 데이터 정합성 문제 때문에 스케일 아웃(대수 늘리기)이 까다로움 → 보통 스케일 업으로 대응
- 대신 서버 1대가 고장 날 걸 대비해 Active/Standby 이중화(HA) 구조를 짬
- Active: 실제 사용자 요청을 실시간 처리하는 메인 DB
- Standby: Active 데이터를 실시간 복제받으며 대기하는 백업 DB, Active 장애 시 Failover로 신규 Active로 전환됨

## 온프레미스 + 클라우드 하이브리드 전략
- 은행처럼 보안이 중요한 곳도 요즘은 하이브리드/멀티 클라우드를 많이 씀
- 핵심 기간계 DB처럼 보안·법적 규제(망분리)가 엄격한 부분은 온프레미스 하이엔드 서버로 직접 구축
- 트래픽이 순식간에 폭증하는 서비스(이벤트, 마케팅 등)는 퍼블릭 클라우드로 처리
- 클라우드의 스케일 아웃 + Auto Scaling으로 트래픽 폭증 시 서버 대수를 자동으로 늘려 대응

## 가상화 (Virtualization)
- 물리 서버 1대를 여러 대의 독립된 가상 머신(VM)으로 나눠 쓰는 기술
- 요즘 서버 성능이 워낙 좋아서, CPU/RAM을 쪼개 서로 다른 OS·환경을 동시에 띄우는 방식으로 활용
- 하이퍼바이저(VMM) 종류
  - Type 1 (Bare-metal): 하드웨어에 직접 올림 (Hyper-V, ESXi). 성능은 좋지만 Hyper-V는 켜고 끌 때 재부팅 필요하고 Type 2 프로그램이랑 충돌 가능
  - Type 2 (Hosted): 기존 OS 위에 프로그램처럼 설치 (VMware, VirtualBox). 실습용으로 편함. VirtualBox는 네트워크 설정이 까다로운 편이라 실무에선 VMware를 더 많이 씀
- 실무에서 쓰는 이유: 비용 절감(자원 효율화), 클라우드(EC2, GCP VM 등)의 기반 기술, VM 단위로 격리돼서 장애 영향 최소화 + 스냅샷으로 빠른 복구 가능

## 멀티테넌시 (Multi-tenancy)
- 하나의 소프트웨어/인프라 인스턴스에서 여러 고객(테넌트)이 데이터를 분리해서 같이 쓰는 구조
- 서버/DB 등 리소스를 공유하니까 비용 절감, 유지보수도 편해짐
- 핵심은 테넌트 간 데이터 격리 보안이랑 부하 분산 관리
