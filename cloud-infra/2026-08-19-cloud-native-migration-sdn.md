# 2026-08-19 프라이빗 클라우드 ~ 마이그레이션 ~ SDN/NFV

## 프라이빗 클라우드 / 클라우드 네이티브
- OpenStack: 오픈소스로 프라이빗 클라우드 직접 구축할 때 쓰는 플랫폼
- Kubernetes: 컨테이너 여러 개를 자동으로 배포/관리해주는 오케스트레이션 도구
- CNCF: 쿠버네티스 같은 클라우드 네이티브 오픈소스 프로젝트들 지원하는 비영리 단체
  - 프로젝트 성숙도는 샌드박스 → 인큐베이팅 → 졸업(Graduated) 순으로 올라감. 실무에서 도구 고를 때 "졸업한 프로젝트인지" 확인하면 안정성 어느 정도 검증된 거라 참고하기 좋음

## 클라우드 마이그레이션 전략 (AWS 6R)
기존 시스템을 클라우드로 옮길 때 딱 하나의 방법만 있는 게 아니고, 상황 봐서 고르는 거임
- 리호스팅: 코드 하나도 안 바꾸고 그대로 클라우드로 옮김 (Lift-and-shift, 제일 빠름)
- 리플랫포밍: 큰 구조는 유지하되 일부만 클라우드에 맞게 최적화
- 리팩터링: 아예 클라우드 네이티브 구조로 다시 설계 (제일 손 많이 감, 대신 클라우드 장점 제일 잘 살림)
- 재구매: 자체 개발한 시스템 버리고 SaaS로 갈아탐 (예: 사내 CRM → Salesforce)
- 유지: 지금 상태 그대로 둠 (아직 옮길 이유가 없거나 못 옮기는 경우)
- 폐기: 안 쓰는 애플리케이션은 그냥 없앰

## AWS Snow 패밀리 (물리 디바이스로 대량 데이터 이전)
- 인터넷으로 옮기기엔 데이터가 너무 많을 때 물리 장비를 보내서 데이터 담아 오는 방식
- Snowcone: 소형, 엣지 환경에서 씀
- Snowball: 본격적인 대규모 마이그레이션용
- Snowmobile: 아예 트럭으로 옮기는 급 (최대 100PB)

## SDN (Software Defined Network)
- 원래는 라우터마다 각자 알고리즘 들고 개별적으로 제어를 했음
- SDN은 이걸 나눠서, 실제 트래픽 처리(Data Plane)는 네트워크 장비가 하고, 제어(Control Plane)는 범용 서버에서 중앙 집중적으로 함
- 이렇게 하면 네트워크 설정을 코드/소프트웨어로 관리할 수 있어서 자동화하기 좋아짐
- OpenFlow: Control Plane이랑 Data Plane을 연결해주는 개방형 표준 인터페이스

## NFV (Network Functions Virtualization)
- 방화벽, 로드밸런서 같은 물리 네트워크 장비 기능을 가상 머신(VNF)으로 구현하는 것
- OVS(Open Virtual Switch): 제일 많이 쓰는 오픈소스 가상 스위치, OpenFlow 기반으로 동작
- SDN이랑 NFV 같이 쓰면 시너지 남 — VNF를 원하는 위치에 유연하게 배치하려면 SDN의 중앙 제어가 필요하기 때문
